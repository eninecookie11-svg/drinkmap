# 제품 정보 수정 안내

화면 코드를 몰라도 `public/data/products.json`만 수정하면 됩니다.
이 파일은 검색·필터·상세·비교에서 사용하는 제품 기본정보와 기존 조사 자료 원본입니다.
검토한 식약처 API 영양정보는 `public/data/drinks.json`에 별도로 저장하며 같은 `productId`에 연결합니다. 해당 제품의 영양·카페인·감미료를 products.json에서 수정해도 API 스냅샷에 덧붙이지 않습니다. 수집·등록과 별도 검증 방법은 [food-api.md](food-api.md)를 참고하세요.
`dist`는 배포할 때 자동 생성되는 복사본이므로 직접 고치지 마세요.

## 가장 자주 하는 수정
1. VS Code에서 `public/data/products.json`을 엽니다.
2. Ctrl+F로 제품 이름을 찾습니다. `{`부터 `}`까지가 제품 하나입니다.
3. 해당 값과 제품의 `source`(출처), `checked`(확인일)를 함께 바꾸고 저장합니다.
4. 터미널에서 `npm.cmd test`를 실행해 잘못된 형식을 검사합니다.
5. `npm.cmd run dev` 실행 후 http://127.0.0.1:4173 에서 검색·상세·비교를 확인합니다.
6. `npm.cmd run build` 후 `dist` 폴더를 Cloudflare Pages에 다시 배포합니다.

현재 대부분의 성분은 **2024년 한국소비자원 시험 제품 기준**입니다.
공식 자료를 읽은 날짜와 실제 현재 제품 라벨을 확인한 날짜는 다릅니다.
현재 포장을 확인하면 `source.scope`를 `2026-11-11 구입 제품 포장 표시 기준`처럼 바꾸세요.
현재 배합의 값과 예전 시험값을 하나의 제품에 혼합하지 마세요.

## 항목 사전
| 항목 | 의미 / 예시 |
|---|---|
| id | 고유 영문 이름. 기존 링크가 연결되므로 수정하지 마세요. 신규 제품은 중복 금지 |
| name / brand / type | 정식 제품명 / 브랜드·제조사 / 음료 종류. 검색·필터는 자동 갱신 |
| flavor / volume | 맛 / 한 캔 용량. volume은 ml 단위 숫자 |
| kcal | 한 캔 열량, 숫자. 0과 미확인(null)은 다릅니다 |
| caffeine | 한 캔 카페인 mg. 미확인 null, 없음 확인 0, 36mg이면 36 |
| caffeineStatus | 참고용 기록. 실제 필터는 caffeine 숫자로 판단합니다 |
| sugar | "0g", "1g", "불검출" 등. 시험 불검출을 표시 0g으로 바꾸지 마세요 |
| carbs / sodium | 한 캔 탄수화물 g / 나트륨 mg. 숫자 또는 null |
| sweeteners | [["수크랄로스", 82, "mg"], ["알룰로스", 6, "g"]] 형식 |
| ingredients | 포장에 적힌 전체 원재료명 문자열. 감미료 이름은 화면에서 자동 강조 |
| allergens | 미확인 null / 확인한 알레르기 ["우유", "대두"] / 표시 없음 확인 [] |
| status | "판매 중 · 2026-11-11 확인", "판매 중단 · 공식 안내 확인" 등 |
| image | 사진 파일 경로. public/assets/photo.webp이면 "assets/photo.webp" |
| imageType | 실제 이미지 설명. 예: "공식 제품 사진 · 사용 허락 확인" |
| color | 제품 카드의 분위기 색. #168261 같은 6자리 색상 코드 |
| source | title(자료명), url(링크), published(발행일), checked(확인일), scope(어떤 제품·언제 기준인지) |
| historicalPrice | 과거 가격 기록. 없으면 null. 현재 가격이라고 해석되지 않게 별도 표시됨 |

**감미료 사용은 확인했으나 양이 없을 때:** `["수크랄로스", null, "mg"]`로 적습니다.
**감미료 자체 미확인:** `sweeteners: []`, 출처도 없으면 `source: null`.
**비어 있는 값은 `null`**로 씁니다. "미확인"을 숫자 칸에 쓰거나 0으로 대체하지 마세요.
`source`는 성분 전체의 근거입니다. 다른 자료를 함께 참고했다면 scope에 항목별 근거를 적고 대표 링크를 넣으세요.

## 새 제품 추가
`docs/product-template.json`을 복사하여 목록의 마지막 제품 다음에 붙입니다.
제품 사이에는 쉼표가 필요합니다. 맨 마지막 제품 뒤에는 쉼표를 쓰지 않습니다.
제품 수와 브랜드·종류 필터, 사전 사용 제품 수는 자동으로 바뀝니다.
사진은 사용 허락을 먼저 확인하고 `docs/image-rights.md`에 기록하세요.
기존 SVG를 바꿀 필요 없이 사진 파일을 넣고 image 경로만 변경하면 됩니다.

## 가격과 사전
- 과거 가격 `regular`는 자료에 기록된 판매가 총액이며, 정가 여부가 입증된 것은 아닙니다.
- `sale`은 확인한 할인 총액, `shipping`은 배송비, `quantity`는 포장 수량, `seller`는 판매처, `date`는 확인 시점입니다.
- 없는 가격·할인가·배송비를 만들어 넣지 마세요. 최신 가격을 기록할 경우 현재 화면의 ‘과거 기록’ 표시 체계도 함께 검토해야 합니다.
- 사용자가 계산기에 넣은 가격과 결과는 저장하지 않습니다. 공용 제품 데이터도 바뀌지 않습니다.
- 감미료 사전은 `public/data/dictionary.json`에서 수정합니다.
- 자료 전체에 관한 안내는 `public/data/source.json`에서 수정합니다. 개별 제품 출처는 각 제품의 source가 우선합니다.

## 저장 후 오류가 나면
`npm.cmd test` 메시지에 제품 id와 잘못된 항목이 나옵니다.
VS Code에서 빨간 밑줄이 보이면 따옴표·쉼표·괄호부터 확인하세요.
색·글꼴·간격은 `public/tokens.css`에서만 변경하세요.

## 기본순·인터넷 조사값 (2026-11-11)

감미료 표시 순서는 현재 products.json에서 불러온 제품별 사용 횟수로 자동 집계됩니다. 한 제품의 같은 감미료는 한 번만 세고, 함량이 null이어도 사용이 확인된 원료는 포함합니다. 카드·상세·감미료 사전·필터에 공통 적용하며 동률은 가나다순입니다. 스테비올배당체·효소처리스테비아는 별도로 셉니다. 과거 외부 20종 조사 파일은 기록으로 보존하지만 화면 정렬에는 사용하지 않습니다.

- ‘기본순’은 products.json 배열 순서입니다. 별도 인지도·판매량 순위가 아닙니다. 카드를 옮기려면 제품 객체 전체의 순서를 바꾸세요.
- 현재 30종입니다. 사용자 요청으로 펩시 파인애플·노브랜드 제로콜라는 목록에서 제외했습니다.
- 카드 하단은 모두 ‘인터넷 조사 결과’로 표시하지만, 상세의 source·caffeineSource는 각각 유지합니다.
- 사용자 제공 카페인은 caffeineSource.evidenceType이 user-provided-internet-research입니다. 접수일과 원문 미확인 범위를 함께 적고, 공식 검증값으로 설명하지 마세요.
- container가 병이면 nutritionBasis는 ‘한 병 기준’으로 표시됩니다. 제품명에 ‘제로’가 있어도 표시 열량을 임의로 0으로 만들지 마세요.
- 새 제품 자료와 적용 보류 사유는 [제품 확대 조사 기록](research/catalog-expansion-2026.md)에 있습니다.


## 항목별 출처가 다른 펩시 자료
펩시 355ml는 사용자 제공 공식몰 영양표·원재료명과, 사용자가 지정한 2024년 한국소비자원 카페인 조사값 46mg을 구분합니다. `caffeineSource`에 카페인 전용 출처·조사 시점·적용 범위를 기록하고 카드·상세·비교에 2024년 조사임을 표시합니다. 최신 카페인 확인값으로 해석하지 마세요.
